
# Lab 3 — MiniCParser

**Дисципліна:** Системне програмування  
**Тема:** Розробка синтаксичного аналізатора на основі Lex/Yacc  
**Мова реалізації:** C++17  
**Інструменти:** Flex, GNU Bison, GCC, Make, Graphviz  
**Середовище:** Ubuntu WSL2, Visual Studio Code

## 1. Опис проєкту

MiniCParser — синтаксичний аналізатор спрощеної підмножини мови C, розроблений із використанням Flex (аналог Lex) та GNU Bison (аналог Yacc).

Програма виконує:

- Лексичний аналіз вихідного коду.
- Синтаксичний аналіз за заданою граматикою.
- Виявлення лексичних і синтаксичних помилок.
- Побудову абстрактного синтаксичного дерева (AST).
- Інтерпретацію арифметичних виразів та операторів.
- Генерацію трьохадресного проміжного коду (TAC).
- Візуалізацію AST засобами Graphviz.

Проєкт реалізує лише визначену підмножину C, а не повний стандарт мови.

## 2. Підтримувані конструкції

### Оголошення змінних

```c
int x;
int y = 5;
```

### Присвоювання

```c
x = 10;
x = x + 2;
```

### Арифметичні операції

Підтримуються:

- Додавання `+`
- Віднімання `-`
- Множення `*`
- Ділення `/`
- Унарний мінус `-`
- Дужки `( )`

Пріоритет операцій задається граматикою Bison.

### Виведення результатів

```c
print(x);
print(2 + 3 * 4);
```

### Коментарі

Підтримуються однорядкові коментарі:

```c
// This is a comment
```

## 3. Архітектура

Обробка програми відбувається за схемою:

```text
Вихідний код (.c)
        |
        v
Flex (lexer.l)
        |
        v
Послідовність токенів
        |
        v
Bison (parser.y)
        |
        v
Абстрактне синтаксичне дерево (AST)
        |
        +--> Виведення AST у термінал
        |
        +--> Інтерпретатор --> Результати обчислень
        |
        +--> Генератор TAC --> output.tac
        |
        +--> Graphviz DOT --> ast.dot --> ast.svg
```

### Основні файли

| Файл | Призначення |
|------|-------------|
| `lexer.l` | Правила лексичного аналізу Flex |
| `parser.y` | Граматика та семантичні дії Bison |
| `ast.h` | Типи та структура вузлів AST |
| `interpreter.h`, `interpreter.cpp` | Інтерпретація програми |
| `codegen.h`, `codegen.cpp` | Генерація трьохадресного коду |
| `ast_visualizer.h`, `ast_visualizer.cpp` | Генерація Graphviz DOT |
| `main.cpp` | Запуск аналізатора та виведення результатів |
| `Makefile` | Автоматизація збирання та тестування |
| `examples/valid.c` | Коректний тестовий приклад |
| `examples/invalid.c` | Приклад із синтаксичною помилкою |

Файли `parser.tab.c`, `parser.tab.h` і `lex.yy.c` генеруються автоматично.

## 4. Встановлення залежностей

У терміналі Ubuntu:

```bash
sudo apt update
sudo apt install -y flex bison g++ make libfl-dev graphviz
```

## 5. Збирання проєкту

Відкрийте термінал у кореневій папці `MiniCParser`:

```bash
make
```

Для повного повторного збирання:

```bash
make clean
make
```

Результат — виконуваний файл `minicparser`.

## 6. Запуск

### Коректна програма

```bash
./minicparser examples/valid.c
```

Програма перевіряє синтаксис, виводить AST, виконує обчислення та генерує проміжний код.

Очікуваний результат обчислень:

```text
Output: 20
Output: 26
```

### Програма з помилкою

```bash
./minicparser examples/invalid.c
```

Очікуваний результат:

```text
Syntax error at line 2: syntax error
Parsing failed.
```

## 7. Проміжний код TAC

Генератор створює трьохадресний код у файлі `output.tac`.

Наприклад, вираз:

```c
int result = x + y * 2;
```

перетворюється на послідовність:

```text
DECLARE result
t1 = y * 2.000000
t2 = x + t1
result = t2
```

TAC є проміжним представленням програми, а не машинним кодом або кодом цільової архітектури.

## 8. Візуалізація AST

Після успішного запуску аналізатора створюється файл `ast.dot`.

Для генерації SVG виконайте:

```bash
dot -Tsvg ast.dot -o ast.svg
```

Файл `ast.svg` містить графічне представлення абстрактного синтаксичного дерева.

Візуалізація показує ієрархію операторів, виразів та змінних, а також пріоритет арифметичних операцій.

## 10. Теоретичні основи

### Лексичний аналіз

Flex розпізнає послідовності символів за регулярними виразами та перетворює їх на токени, які передаються синтаксичному аналізатору.

### Синтаксичний аналіз

GNU Bison генерує синтаксичний аналізатор на основі контекстно-вільної граматики.

У проєкті задано правила для оголошень, присвоювань, викликів `print()` та арифметичних виразів.

### LALR-аналіз

LALR(1) — метод синтаксичного аналізу зліва направо, який будує правий вивід у зворотному порядку та використовує один токен випередження.

Bison використовує таблиці станів і дій для визначення наступного кроку аналізу.

### Конфлікти граматики

- `shift/reduce` — неоднозначність між зсувом наступного токена та згортанням правила.
- `reduce/reduce` — неоднозначність між двома можливими згортаннями.

У граматиці визначено пріоритет і асоціативність арифметичних операторів за допомогою `%left`, `%right` та `%prec`.

## 11. Обмеження

Поточна реалізація не підтримує повний синтаксис C/C++, зокрема:

- `if`, `else`, `while`, `for`;
- визначення користувацьких функцій;
- масиви, вказівники та структури;
- логічні оператори;
- декілька типів даних.

Попри використання ключового слова `int`, інтерпретатор зберігає числові значення як `double`. Це спрощення навчальної реалізації.

## 12. Висновок

У лабораторній роботі реалізовано лексичний і синтаксичний аналізатор спрощеної мови C із використанням Flex та GNU Bison.

На основі граматики побудовано AST, реалізовано виконання арифметичних виразів, генерацію проміжного коду TAC та графічне представлення дерева за допомогою Graphviz.
